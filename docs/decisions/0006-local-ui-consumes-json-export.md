# 0006: Local UI Consumes JSON Export

## Status

Accepted

## Context

AgentViz needs a local UI that visualizes Markdown agent run registries. The project already has a CLI parser, validator, and JSON export contract. If the UI independently parses Markdown, the CLI and UI may drift in how they interpret schema fields, sections, statuses, and findings.

## Decision

The V0 local UI will consume `agentviz-export-v0` JSON generated by `agentviz export --json`.

Markdown remains canonical. The CLI owns parsing, validation, and export normalization. The UI owns presentation, filtering, timeline display, warning triage, and run detail rendering.

## Consequences

Positive:

- CLI and UI share one registry interpretation.
- UI implementation can start from a stable data shape.
- UI tests can use fixture-generated JSON.
- Malformed Markdown handling remains centralized in validation.

Tradeoffs:

- The UI needs a refresh/generation path before it can show current data.
- A purely static browser UI may need the user or CLI to provide/export JSON.
- Some source-file affordances may require CLI assistance because browsers cannot freely open local files.

## Alternatives Considered

### Browser Parses Markdown Directly

This would let the UI point at a workspace and parse files itself, but would duplicate parser and validation logic across runtimes.

### UI Uses Markdown Files Only

This would keep the UI closer to the canonical backend, but would make filtering, warnings, and timeline rendering harder to keep consistent with CLI output.

### Hosted Backend

A hosted backend would simplify refresh and persistence but conflicts with the V0 local-first constraint.
