# Dogfooding AgentViz

Status: V0 draft.

AgentViz uses a committed `agents/` workspace at the repository root to track its own project work. This keeps the product honest: the same Markdown registry, linter, and JSON export that users rely on should also explain the state of AgentViz itself.

## What We Track

Track project-level work when it helps another human or agent understand the state of the repo:

- milestone planning,
- design decisions,
- implementation runs that produce durable artifacts,
- release readiness,
- handoffs between issues, PRs, and agent threads.

Do not track every tiny command, formatting pass, or transient local thought. The registry should stay useful as a command center, not become a complete chat transcript.

## What Lives In The Repo

Commit files that describe public project state:

- `agents/index.md`: the current AgentViz dashboard,
- `agents/schema.md`: the local operating contract generated by `agentviz init`,
- `agents/log.md`: registry-level maintenance events,
- `agents/runs/*.md`: public project-level runs,
- docs that explain the dogfood workflow.

Committed run notes may link to public GitHub issues, PRs, docs, source files, and release artifacts.

## What Stays Local Only

Keep private or noisy material outside the committed repo:

- provider transcripts that contain private context,
- credentials, tokens, account identifiers, or customer information,
- scratch experiments that do not affect public project direction,
- local machine paths that would not make sense to contributors,
- personal productivity notes that are not part of AgentViz project state.

If a private run creates a public artifact, commit only the project-level summary and artifact links.

## Updating The Dogfood Workspace

Use the CLI against the repo root:

```sh
npm run dev -- status .
npm run dev -- lint .
npm run dev -- export --json .
```

When updating a run note:

- change `updated`,
- adjust `status`, `check`, and `next_action` when attention changes,
- append a timestamped `Timeline` entry,
- add durable artifacts,
- keep `agents/index.md` linked to every run,
- record registry-level changes in `agents/log.md` when the dashboard or workspace structure changes.

## v0.1 Release Story

The dogfood workspace should make the v0.1 path visible:

1. The Markdown registry schema is stable enough for real notes.
2. The CLI can initialize, read, lint, summarize, and export a workspace.
3. The JSON export contract gives the local UI a stable read model.
4. The UI plan defines the first visual command center.
5. The repo tracks its own active and completed work using AgentViz.
6. The release checklist can point to real dogfood output instead of hypothetical examples.

## QA

Before merging dogfood updates, run:

```sh
npm run dev -- lint .
npm run dev -- export --json .
npm run verify
```

The repo-root workspace should lint cleanly unless the PR intentionally demonstrates a warning or error, and that intent should be documented in the PR.
